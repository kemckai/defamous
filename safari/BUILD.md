# Building Defamous for Safari on macOS

The native wrapper lives in `safari/Defamous/Defamous.xcodeproj`. It was generated by Xcode 26.5’s Safari web extension converter and then checked in. The app target is `com.kemckai.Defamous`. The extension target is `com.kemckai.Defamous.Extension` in both Debug and Release. `ViewController.swift` uses that same extension identifier when it asks Safari whether the extension is enabled.

Web extension files are not edited inside the Xcode tree. `content.js`, `popup.html`, `popup.js`, `manifest.json`, and the three toolbar icons at the repository root are the source of truth. `safari/sync-extension-resources.sh` copies those seven files into `safari/Defamous/Defamous Extension/Resources/` and deletes anything else in that directory. The extension target runs that script as its first build phase, and `safari/build-mac.sh` runs it before `xcodebuild`.

`manifest.json` includes `host_permissions` for `*://*.facebook.com/*`. Safari uses that list for the extension’s Websites permission.

This project does not target iOS. The content script matches the desktop `www.facebook.com` DOM. `m.facebook.com` is a different page and is not filtered.

## What is already known about a running copy

On the machine where this wrapper was first built:

- Defamous is filtering Facebook posts in the current Safari session.
- The copy that is installed is ad-hoc signed.
- A separate Release build signed with an Apple Development identity succeeded and was not installed.
- Whether the enabled extension is still on after Safari is quit and reopened has not been verified.

Nothing in this repository installs an app or changes Safari on a machine that already has Defamous running.

## Two ways to load it

### Per-session unsigned development

`safari/build-mac.sh` with no `DEVELOPMENT_TEAM` signs the app ad-hoc (`CODE_SIGN_IDENTITY=-`, Sign to Run Locally).

Safari loads an ad-hoc extension only while **Develop → Allow Unsigned Extensions** is enabled. On current macOS that checkbox applies to the current Safari session. Quitting Safari turns it off. Because restart persistence has not been verified, do not treat an ad-hoc enablement as something that stays on after Safari restarts.

### Apple Development signature

Set a team id without committing it:

```bash
cp safari/Defamous/Local.xcconfig.example safari/Defamous/Local.xcconfig
# edit Local.xcconfig and set DEVELOPMENT_TEAM to your team id
```

or export it only for the build:

```bash
DEVELOPMENT_TEAM='YOUR_TEAM_ID' CONFIGURATION=Release safari/build-mac.sh
```

`Local.xcconfig` is gitignored. `Signing.xcconfig` is the committed default and leaves `DEVELOPMENT_TEAM` empty. A Release build produced this way is not the app that is currently installed. Installing it would replace the ad-hoc copy and is a separate step from building.

## Build

Requirements: a Mac with Xcode (the project was generated by Xcode 26.5; the app target inherits `MACOSX_DEPLOYMENT_TARGET = 26.5`, and the extension target is 10.14).

```bash
safari/build-mac.sh                  # Debug, ad-hoc if no team is set
CONFIGURATION=Release safari/build-mac.sh
safari/build-mac.sh --sync-only      # refresh Resources and stop
```

The product is under `safari/build/`. `safari/DerivedData/` and `safari/build/` are gitignored. The script stops after compile. It does not copy the app into `/Applications`, does not open Safari, and does not toggle extension permissions.

To build from Xcode instead, open `safari/Defamous/Defamous.xcodeproj`, select the shared **Defamous** scheme, and build. The sync phase still runs first. Put a team id in `Local.xcconfig` if you want Automatic signing; otherwise use Sign to Run Locally for an ad-hoc build.

## Enable on Facebook

1. Open the built `Defamous.app` once so macOS registers the extension.
2. Safari → Settings → Extensions, and turn Defamous on.
3. For an ad-hoc build, also enable Develop → Allow Unsigned Extensions for this Safari session.
4. Safari → Settings → Extensions → Defamous → Websites, and set `facebook.com` to Allow. That row is there because of `host_permissions`.
5. Load `https://www.facebook.com/` and confirm celebrity, verified, shared-from-page, and high-engagement posts are hidden. The toolbar popup uses `chrome.storage.sync`, which Safari exposes to web extensions.

Quit Safari and open it again before deciding that an enablement persists. That check has not been done.

## What not to commit

Certificates, private keys, provisioning profiles, team ids, Apple IDs, `Local.xcconfig`, `xcuserdata`, `DerivedData`, archives, and built `.app` / `.appex` bundles stay out of git. See `.gitignore`.
